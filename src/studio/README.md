# VCM Studio backend

FastAPI API (phase U1) + SQLite/SQLModel DB (phase U0) on top of the existing
Aventure brain (`src/pipeline.py`, `src/features/`). Additive: the legacy
Streamlit app and the golden pipeline are untouched.

## Run the API

```bash
.venv/bin/uvicorn src.studio.api.app:app --reload
```

Interactive docs at <http://localhost:8000/docs>. CORS is open for the Vite
front at <http://localhost:5173>.

## Environment variables

| Var | Default | Purpose |
|---|---|---|
| `VCM_STUDIO_DB` | `sqlite:///studio.db` | DB URL. Use a **file** DB, not `:memory:` (in-memory is not shared across connections). |
| `VCM_OUTPUT_DIR` | `exports` | Base directory for generated assets (images/video/audio) and final videos. |
| `OPENAI_API_KEY` | _(unset)_ | When set, scripts are generated by GPT (`OpenAIAdventureDecomposer`); otherwise the deterministic `FakeAdventureDecomposer` is used. |
| `REPLICATE_API_TOKEN` | _(unset)_ | Required for real asset generation. |

### Output directory on the host

`exports/` is often **root-owned** (created by a Docker run), which makes asset
generation fail with `PermissionError`. On the host, point the output at a
user-writable directory:

```bash
VCM_OUTPUT_DIR=./studio_output .venv/bin/uvicorn src.studio.api.app:app --reload
```

`studio_output/` is gitignored. The directory is created on demand. File-serving
routes (`/api/assets/{id}/file`, `/api/episodes/{id}/video`) read from the same
base via the stored local paths.

## Tests

```bash
.venv/bin/python -m pytest tests/test_studio_api.py tests/test_studio_services.py -q
```

The suite is fully offline: the asset provider, the downloader, and the montage
backend are mocked, so no network call and no FFmpeg are needed.
